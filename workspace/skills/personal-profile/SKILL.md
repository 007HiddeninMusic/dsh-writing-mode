# 个人简介 / 成就清单

## 一、动笔前必须问清

- **用途**：简历开头 / 奖项申报 / 个人主页 / 会议介绍 / 开场自我介绍
- **长度档位**：半页（150–200 字）/ 一页（400–500 字）/ 长版（800–1000 字）
- **人称**：第一人称（自我介绍）/ 第三人称（申报材料、主持人介绍）
- **读者**：专业同行 / 非专业评委 / 招聘方
- **必须出现**与**不能出现**：某段经历、某家单位、某个数字

然后**先读 `facts\个人事实库.md`**，再动笔。

## 二、结构（三档通用）

1. **定位句**（1–2 句）：你是谁 + 最强的一个证据。不要"热爱生活、积极向上"这类。
2. **2–3 条支撑经历**：每条 = 做了什么 + 结果（数字/影响）。按与用途的相关度排序，不按时间。
3. **收尾**：能力范围或下一步方向，一句。不要喊口号。

三档的区别只是**支撑经历的条数与展开程度**，不是靠形容词加水。

## 三、把职责改写成结果

| 不要写 | 改写成 |
|---|---|
| 负责 XX 项目 | 主导 XX，把 Y 从 A 降到 B（半年内） |
| 参与 XX 建设 | 承担 XX 模块，上线后覆盖 N 名用户 |
| 具有较强的组织能力 | 组织 N 场活动，最大一场 N 人，零事故 |
| 获得广泛好评 | （删掉，或换成具体评价/排名/转载数） |

规则：**每个支撑经历至少有一个人能追问的数字**。没有数字的，就是没写。

## 四、禁用清单

- 形容词堆砌：优秀、卓越、热爱、扎实、严谨、充满热情
- 无宾语的动词：负责、参与、协助、推动（后面必须接具体对象和结果）
- 万能句式：具有较强……能力 / 在工作中不断提升自我 / 始终保持学习热情
- 自我评价式的结论：深受好评、获得认可、得到一致肯定

用户没说过的，一律不写——包括奖项等级、职务、数字、他人评价。

## 五、让简介不像模板

- 找**一条别人不会有的细节**（一个奇怪的经历、一个具体的数字、一个反差），放在定位句或收尾。
- 真话优先于漂亮话：宁可写"做过 3 个失败的项目"，也不要写"积累了丰富经验"。
- 长版里允许一条稍长的叙事；半页版只留最硬的证据。

## 六、交付

- 默认 Markdown 正文 + 字数（`_tools\wordcount.py`，注明口径）。
- 正式提交时给 `.docx`（office-docx 技能），按要求排版。
- 附一份 **`【待补】` 清单**：哪些事实是用户没给、需要补的。
- 用户给的是旧版简介时：**只改表达，保留全部事实与数字**，并列出改动清单（见 AGENTS.md 第二节）。

## 七、交稿前自检

- [ ] 每一句都能被追问，且答得上来
- [ ] 每个支撑经历都有一个数字或一个可验证的结果
- [ ] 没有用户未提供的奖项、职务、数字、评价
- [ ] 没有出现禁用清单里的词
- [ ] 人称一致；第三人称时不自称"我"
- [ ] 字数落在档位区间内
- [ ] 全文删掉任意一段，还成立吗？成立的那段在凑数
