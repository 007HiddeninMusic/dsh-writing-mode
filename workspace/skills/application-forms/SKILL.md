# 申请表 / 表单回填

表单是**格式敏感 + 事实密集**的活。两者都不能出错：字段错了要重填，事实编了要出事。

## 一、动笔前必须先解析原表

拿到原表格（`.docx` / `.xlsx` / 图片 / 网页表单文字）后，**先把结构读出来**，输出一张清单给用户确认：

| 字段名 | 类型 | 字数上限 | 是否必填 | 备注 |
|---|---|---|---|---|
| 姓名 | 文本 | — | 是 | |
| 个人陈述 | 长文本 | 500 字 | 是 | 超出会被截断 |
| 获奖情况 | 多行文本 | 300 字 | 否 | |

规则：

- 字段名**原样照抄**，不美化、不改写、不合并。
- 字数上限从表格里读（有"不超过 X 字"提示的）；读不到的，标注"未标明"并问用户。
- 有下拉选项/勾选框的，列出全部选项。
- 有格式要求的（日期格式、单位、附件），单独标出。

**不要跳过这一步直接写内容**——字段没对齐，写得再好也要重来。

## 二、事实来源

- 一切具体事实**只从 `facts\个人事实库.md` 取**，或从用户本次提供的材料取。
- 库里没有的字段 → 写 `【待补：字段名】`，不要编、不要"大概"、不要用"多项""若干"糊过去。
- 涉及数字（排名、金额、人数、时长）的，与库中数值**逐字一致**，不换算、不四舍五入、不夸大。

## 三、填写规则

1. **不增删字段**，不改字段顺序，不改字段名。
2. 每个字段写到上限的 **85%–98%**：太短显得敷衍，超了会被截断。
3. 长文本字段（个人陈述、申请理由、经历说明）用这个结构：
   **是什么 → 我做了什么 → 结果（数字）**
   不要写成散文化的抒情，也不要只写职责不写结果。
4. 短字段（一句话介绍、特长）优先塞**可验证的具体事实**，不写形容词。
5. 多个字段之间**不要重复同一句话**——评委连着看，重复会显得没内容。
6. 不写无据的程度副词："极大提升""显著改善""广泛好评"。

## 四、交付

1. **回填后的文件**：在原表格上填，保留原格式（用 office-docx / openpyxl 技能）。另存为新文件，不覆盖原件。
2. **待补清单**：所有 `【待补】` 逐条列出，标明字段名。
3. **字数核验表**：每个有上限的字段，实际字数 / 上限，用 `_tools\wordcount.py` 数。

## 五、交表前自检

- [ ] 每个字段都填了（或明确标了【待补】）
- [ ] 没有任何字段超字数
- [ ] 字段名与原表完全一致，没有增删
- [ ] 所有数字与 facts 库一致
- [ ] 没有编造的经历、奖项、职务、单位
- [ ] 字段之间没有重复的句子
- [ ] 原文件未被覆盖
