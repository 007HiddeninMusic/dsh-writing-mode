# 网络小说

网文最难的不是文笔，是**连续性**。写到第 30 章崩设定，读者立刻跑。所以这个技能的重点是账本，不是形容词。

## 一、动笔前必须问清

- **平台与题材**（男频/女频、都市/玄幻/悬疑…），平台有字数与更新要求的一并问
- **单章字数**与更新节奏（日更一章 / 一次多章）
- **视角与人称**（第一人称 / 第三人称限知 / 全知）
- **主线目标**：主角最终要什么？反派/阻力是谁？
- **是否已有设定**：有就让我先读 `设定集.md`、`人物卡.md`、`前情提要.md`
- **禁忌**：不能写的现实人物、机构、题材红线

已有前情提要时，**先读完再动笔**，不要凭印象续写。

## 二、四本账（长篇不崩的根本）

放在项目目录下，随写随更：

| 文件 | 内容 | 更新时机 |
|---|---|---|
| `设定集.md` | 世界观、力量体系/规则、地理、组织、货币、时间线 | 新增设定时 |
| `人物卡.md` | 每人一行：姓名 / 身份 / 目标 / 秘密 / 说话习惯 / 关键关系 | 新角色出场时 |
| `前情提要.md` | 截至最新一章的剧情摘要（分段，越长越粗） | **每写完一章** |
| `伏笔台账.md` | 埋了什么 / 第几章埋 / 计划第几章回收 / 状态 | 埋或回收时 |

## 三、续写流程（严格执行）

1. 读 `前情提要.md` + `伏笔台账.md` + **最近 2 章正文**（不是只看摘要，语感要接上）
2. 确认这一章要推进什么（一个目标，不要一章塞三件事）
3. 写正文
4. **更新前情提要**（加一段本章摘要）
5. 更新伏笔台账（新埋的登记，回收的标记）
6. 跑一遍下面的矛盾自检

## 四、单章结构

- **开头 100 字内**必须给钩子：一个新信息、一个麻烦、一句反常的话。禁止用环境描写开头。
- **中段**：冲突升级，主角做选择。每章至少一个**信息增量**（新线索/新关系/新能力）。
- **结尾断章**：留一个问题或一个未落地的动作。不要写"欲知后事如何"，也不要总结本章。

## 五、节奏（爽点与铺垫）

- **黄金三章**：第 1 章给主角困境与性格，第 2 章给一次明确的兑现（爽点），第 3 章给长线目标。
- 连续铺垫不超过 **3 章**必须有一次兑现，否则读者走。
- 爽点类型轮换：实力提升 / 打脸 / 身份揭示 / 情感确认 / 意外收益。同一个类型连着用会疲。
- 每 5–10 章安排一次小高潮，每 30 章左右一次大转折（按平台节奏调整）。

## 六、语言

网文重"顺"，不重"雅"：

- 短句为主，一段不超过 4 行。
- 对话推进剧情，少用大段心理描写。
- 少用四字成语堆砌、少用华丽比喻。
- 人物说话要有区分度：同一句话，换个角色说应该听得出不同。
- 每章开头**不要回顾上一章**（读者刚看过）。

## 七、矛盾自检（每章交付前）

- [ ] 人物姓名、称呼、身份前后一致（别把"老王"写成"王叔"）
- [ ] 时间线可推（第几天、什么季节、伤势恢复了没有）
- [ ] 能力上限没被突破（主角这一章突然变强有没有交代）
- [ ] 已死/已退场角色没有复活
- [ ] 地理距离合理（不能一天从城南到城北三次）
- [ ] 本章埋的伏笔已登记进台账
- [ ] 前情提要已更新
- [ ] 单章字数达标（用 `_tools\wordcount.py` 数，不要估）

## 八、交付

- 默认：对话里给本章正文 + 字数（按平台口径）。
- 用户要存档时：写入 `projects\网文\<书名>\第NNN章-标题.md`。
- 每次交付附一句：**本章推进了什么 / 埋了什么 / 下一章要接什么**。
- 需要投稿排版时生成 `.docx`（office-docx 技能）。
