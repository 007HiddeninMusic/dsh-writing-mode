# DSH 写作模式

给 [DeepSeek Harness (DSH)](https://github.com/deepseek-ai) 用的**写作专用 Agent 模式**。

切到这个模式，AI 就不再是一个"会写代码的助手"，而是一个懂征文、论文、网文、申请表、个人简介的写作搭子——并且**不会编造引用、不会编造你的经历、不会给你估字数**。

---

## 它解决什么

通用 AI 写作有四个稳定的坑，这个模式逐条对症：

| 坑 | 这个模式怎么处理 |
|---|---|
| **编造参考文献** | 硬规则：只用本会话实际检索到、能给出链接/DOI 的来源；查不到就留 `【待补】`；每处引用登记进台账，**台账里没有的不许进正文** |
| **编造你的经历和数字** | 硬规则：一切关于你的事实只从 `facts/个人事实库.md` 取；库里没有就留占位符，交付时列清单 |
| **字数靠估** | 内置工具，一次给四种口径（汉字 / 汉字+标点 / 含空格 / 中英词数）。征文被"超 30 字"刷掉这种事不该发生 |
| **改一句就重写全文** | 规则：默认定点修改，只动你指出的地方，并给「原文 → 改为 + 理由」的改动清单 |

另外两件小事，但很影响体验：

- **动笔前先反问**（读者/字数/体裁/截稿/必含项/禁忌，一次问全）
- **动笔前先读你的风格样本**，模仿你的语气，而不是输出通用 AI 腔

## 五种文体，五个技能

技能是**按需加载**的：写到哪类才加载哪类的规则，平时不占上下文。

| 技能 | 覆盖 |
|---|---|
| `literary-contest` | 文学征文、散文、演讲稿、主题文章、比赛投稿 |
| `research-paper` | 课程论文、期刊小论文、会议短文、摘要、文献综述 |
| `web-novel` | 网络小说、连载、续写、设定管理 |
| `application-forms` | 申请表、报名表、推荐表、任何有字段和字数上限的表单 |
| `personal-profile` | 个人简介、自我介绍、成就清单、奖项申报 |

其中 `web-novel` 的重点不是文笔，是**连续性**：设定集 / 人物卡 / 前情提要 / 伏笔台账四本账，加一套强制的续写流程和矛盾自检。

## 目录结构

```
.
├─ README.md                    你正在看的
├─ INSTALL.md                   安装步骤（含验证与回滚）
├─ preset/
│  └─ writing.preset.yml        模式本体：一条 patch 层的 insert 行
├─ workspace/                   这部分会成为你的"写作根目录"
│  ├─ AGENTS.md                 规则手册 —— 改这里就能改行为，不用重启
│  ├─ skills/                   5 个技能
│  ├─ facts/                    个人事实库（模板）
│  ├─ style-samples/            风格样本库（放你的旧作）
│  ├─ _tools/                   字数统计、引用台账模板、两个校验脚本
│  └─ projects/                 分文体存放项目
└─ docs/
   ├─ how-it-works.md           这个模式在 DSH 里是怎么拼出来的
   └─ gotchas.md                
```

## 快速开始

```bash
git clone https://github.com/007HiddeninMusic/dsh-writing-mode.git dsh-writing
```

然后把 `workspace/` 复制到你想要的位置，再把 `preset/writing.preset.yml` 追加到 DSH profile 的 `cordis.patch.yml`，改掉里面的路径占位符。

**完整步骤、验证方法、回滚方法都在 [INSTALL.md](INSTALL.md)。**

## 设计取舍

**为什么是一个模式 + 五个技能，而不是五个模式？**
DSH 的模式只能在会话开始时选，中途不能切换。拆成五个模式意味着你写篇征文要切一次会话、写篇论文再切一次。一个模式挂五个按需加载的技能，切换成本从"换会话"降到"零"。

**为什么保留命令行？**
本来想按"写作不写代码"把 shell 全关掉。但 `.docx` 交付要跑 `python-docx`——关掉就交不出 Word 文件。所以命令行保留，改用规则约束成"只用于文档生成与检查"。

**为什么规则写在 AGENTS.md 而不是模式配置里？**
模式配置改一次要重载；AGENTS.md 是纯文本，改完下次会话就生效，你自己就能改，不用找我。

**为什么不内置"审稿人"技能？**
可以先不加。真需要对抗式复核时，让我以评委身份挑刺比常驻一个技能更省上下文。想加的话 `skills/README.md` 里有格式说明。
